# Booth Navi

複数イベントで再利用できる、ブラウザ完結型のイベント会場マップ作成・閲覧ツールです。主催者は会場図とブース情報を編集でき、参加者は検索、お気に入り、訪問済み、ブース詳細を利用できます。

公開予定 URL: <https://roki0i.github.io/booth-navi/>

## 1. サービス概要

Booth Naviは、イベントごとに名称、テーマ、画像、会場マップ、ブースを差し替えられる静的Webアプリです。バックエンド、外部API、ログインは使用しません。

## 2. 解決する問題

画像やPDFだけの会場図では、スマートフォンで目的の出展者を探したり、訪問状況を管理したりしにくいことがあります。本ツールは検索可能な会場図と、主催者自身が配置を調整できるエディターを一つにまとめます。

## 3. 閲覧モード

- 表記揺れを吸収するブース番号検索
- 複数語AND検索
- ひらがな・カタカナをまたぐ検索
- サークル名・出展者名、ジャンル、商品・配布物名の検索
- ブース詳細、商品・配布物、支払い方法、外部リンク
- イベントごとに分離されたお気に入り・訪問済み
- マップの拡大、縮小、全体表示への復帰
- PC・スマートフォン対応

## 4. 編集モード

- イベント一覧、選択、新規作成、複製、確認付き削除
- サンプルイベントへのリセットと最後に開いたイベントの復元
- イベント名、略称、日付、会場、説明のリアルタイム編集
- 5色とフォントスタイルによるテーマ設定
- ブース情報、座標、商品・配布物の編集と必須項目・番号重複警告
- 自動保存状態（保存中、保存しました、保存できませんでした）の表示

PCでは設定・マップ・ブース編集の3ペイン、スマートフォンでは3つのタブで表示します。

## 5. マップエディター

マップ上の空いている場所をクリックしてブースを追加できます。Pointer Eventsによるマウス・タッチのドラッグ移動、8方向リサイズ、範囲制限、最小サイズ、複製、確認付き削除、元に戻す・やり直す、ズームに対応しています。座標とサイズはマップ全体を100%とした割合で保存されます。

グリッド表示とグリッドへのスナップは個別に切り替えられます。スナップ有効時は、追加、移動、リサイズ、数値入力、複製で`x`、`y`、`width`、`height`が設定したグリッド間隔に揃います。既存データは、選択中またはすべてのブースをまとめてグリッドに合わせられます。

Shift＋クリックで複数のブースを選択し、上下左右の整列、縦横の等間隔配置、幅・高さの統一ができます。キーボードでは矢印キーで移動、Shift＋矢印キーで大きく移動、Delete／Backspaceで削除、Escapeで選択解除できます。入力欄の編集中はショートカットが作動しません。

## 6. 画像アップロード

イベントロゴ、メインビジュアル、ページ背景、会場マップ、ブースのお品書きにPNG、JPEG、WebPを使用できます。プレビュー、削除、代替テキスト、形式エラー、5MB超過警告に対応します。背景画像上には可読性を保つオーバーレイを適用します。

## 7. CSVの読み込み

UTF-8 CSVのプレビュー、必須項目の検証、不正行一覧、ブース番号の重複警告、追加・置き換え、テンプレート保存に対応します。列は`boothNumber,circleName,area,genre,description,x,y,width,height,xUrl,shopUrl`です。引用符と引用符内のカンマを扱える小規模な内製パーサーを使用しています。

## 8. JSONの読み込み・書き出し

`schemaVersion`を含む`EventProject`をJSONで書き出し、検証後に現在のイベントへ上書き、または新規イベントとして追加できます。不正なJSONや必須項目不足は拒否します。画像BlobはJSONに埋め込まず、画像参照のみを書き出します。そのため別ブラウザへJSONだけを移すと画像は復元されません。


## 11. テスト

```bash

```

## 12. データ保存方式

イベント設定、ブース、マップ、画像参照、最後に開いたイベントは`localStorage`へ自動保存します。画像本体は構造化データと分離し、BlobとしてIndexedDBへ保存します。お気に入りと訪問済みのキーにはイベントIDを含めます。IndexedDBが利用できない場合は画像保存エラーを表示し、イベント編集や閲覧は継続できます。

## 13. プライバシー

イベントデータと画像はブラウザ内だけで処理され、外部サーバーや外部APIへ送信されません。ブラウザのサイトデータを削除すると保存内容も失われます。

## 14. 画像利用時の注意

同梱する24件のブース、名称、説明、会場図はすべて架空です。実在イベントの公式ロゴ、会場図、写真、イラストを権利者の許可なく使用しないでください。

## 15. 現在の制限

- 端末間同期、共同編集、ログイン、公開用URL発行はありません
- JSONにはIndexedDB内の画像Blobを含めないため、画像の端末間移行はできません
- 単一フロアのマップを対象とし、複数フロアや巡回ルート提案はありません
- IndexedDBやlocalStorageの容量・保持期間はブラウザに依存します
- ピンチジェスチャーによるズームはなく、ボタンで倍率を変更します

## GitHub Pages

`.github/workflows/ci.yml`は全ブランチ向けのPRの作成・コミット追加・再オープン時に、`npm ci`、`npm test`、`npm run lint`、`npm run build`、Chromiumのインストール、`npm run test:e2e`を順に実行します。同じPRへの追加更新では古いCIをキャンセルします。PR用CIには読み取り権限だけを与え、デプロイは行いません。E2Eレポートと失敗時のトレース・スクリーンショットはArtifactsに7日間保存します。

`.github/workflows/deploy-pages.yml`は`main`へのpush時、または手動実行時にNode.js 24で依存関係を復元し、lint、テスト、ビルド後に`dist`を公開します。PR用CIとは別の同時実行グループを使います。Viteの`base`は`/booth-navi/`のまま維持しています。

### E2Eテスト

Node.js 24で実行します。既存のVitestテストに加えて、PlaywrightのChromiumで8件のE2Eを実行します。

```sh
npm ci
npx playwright install chromium
npm test
npm run lint
npm run build
npm run test:e2e
```

Linuxでブラウザのシステム依存も必要な場合は`npx playwright install --with-deps chromium`を使用します。`test:e2e`はE2Eコードをstrictで型チェックしてから、ビルド済みの`dist`をVite previewで配信します。先にビルドし、ポート4173を空けておいてください。サーバーはテスト終了時に停止します。

- 検索 → 詳細 → お気に入り → 再読み込み後の維持
- ブース追加 → マウスドラッグ → Undo（移動と追加の取り消し）
- Aの編集 → Bへ切り替え → B側の編集をUndoしても両イベントを維持
- 画像付きイベントを複製 → 複製先の参照削除 → 再読み込みした元イベントで画像のデコードを確認
- JSONの構文エラー・スキーマエラーの各1件。正常な取り込み候補の後に不正ファイルを読み込み、上書き操作が残らず保存済みデータも変わらないことを確認
- IME相当の`isComposing`・`keyCode: 229`の各1件。合成Enterでは選択せず、通常Enterでは選択することを確認

各テストは独立したブラウザコンテキストを使い、localStorage・IndexedDBはモックしません。CIは1 worker、失敗時のみ1回再試行します。HTMLレポートは`npx playwright show-report`で確認できます。生成物の`playwright-report/`と`test-results/`はGitとlintの対象外です。

対象はデスクトップChromiumです。Firefox・WebKit・モバイル・OSの実際の日本語IME操作は未検証です。また、画像なしマップでは既存の装飾背景要素が内側のクリックを受け取り、ブース追加に反応しません。このE2Eでは操作可能な外周の余白から追加します。内側の追加不具合の修正は今回の対象外です。

### 保存の完了と終了時の扱い（H5）

- イベント編集は250msのdebounceで保存し、ページ非表示・pagehide・beforeunload・アンマウント時にも未保存の最新状態をlocalStorageへ同期保存します。失敗は保存エラーとして表示し、未保存状態を次の編集または終了通知で再試行します。
- 画像はIndexedDBのrequest成功ではなくtransaction完了を待ってから参照を反映します。中断・エラー時には既存画像の参照を保ちます。
- お気に入り・訪問済みは操作時に同期保存し、失敗時には保存済みの状態を保ってエラーを表示します。再操作で再試行できます。
- ブラウザやOSの強制終了では終了イベントが発火しないことがあり、待機中の編集や未完了の画像保存は保証できません。終了イベントから非同期のIndexedDB完了を待つことも保証できません。
- イベント本体と最後に開いたイベントIDは別キーのため一括確定ではありません。本体保存後にID保存だけが失敗する場合もエラー表示になります。IndexedDBとlocalStorageも一括確定ではなく、画像確定後のイベント保存失敗では未参照Blobが残る場合があります。
- 複数タブの同時編集は後から保存した内容による上書きが起こり得ます。終了時保存も競合し得ますが、今回タブ間同期・競合解決は実装していません。
